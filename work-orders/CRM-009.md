# CRM-009 — crm-beta UAT mode: direct LAN HTTP, beta user provisioning, and a common UAT password

- **Version:** v1.0, 2026-11-11.
- **Authority:** the PO/Architect "CRM-BETA — FINAL UAT DIRECTION" (2026-11-11). crm-beta is a temporary, internal, single-tester UAT environment. It is reached directly over plain HTTP on the LAN, with no external HAProxy, no TLS and no public hostname. The production HTTPS mode stays the default for future deployments.

## Why
crm-beta (CRM-007/007R) currently accepts only production mode:
- `CRM_SITE_URL` must be `https://<CRM_BETA_HOSTNAME>`;
- the edge admits 1–4 `/32` upstream HAProxy hosts;
- crm-app's Apache sets `SetEnv HTTPS on` unconditionally.

Served over plain HTTP, the last point makes EspoCRM treat every request as HTTPS. The likely result is broken redirects and secure-only cookies, so login fails.

There are two further gaps:
- `provision_users.py` accepts only `dev`;
- it issues each user their own random temporary password. The PO wants one common UAT password for the enabled staff accounts, kept separate from the admin and integration credentials.

## Change
1. **`CRM_BETA_MODE`** in the beta env file: `production` (the default when the name is absent or empty) or `uat`. Any other value is refused. Every existing production rule and test stays as it is.
   - **production:** unchanged.
   - **uat:**
     - `CRM_BETA_HOSTNAME` must be empty or absent.
     - `CRM_SITE_URL` must be exactly `http://<CRM_BETA_BIND_IP>:<CRM_BETA_PORT>` (an optional trailing `/` is allowed).
     - `CRM_BETA_UPSTREAM_SOURCES` lists 1–4 space-separated RFC 1918 IPv4 **networks**, each `a.b.c.d/N` with N from 16 to 32 and the network address exact (no host bits set). The authorised LAN sources go here.
       - Refuse any entry that overlaps a Docker bridge subnet, using the same idea as the dev check. At minimum refuse 172.16.0.0/12 entries that overlap the crm-beta and crm-dev compose networks. Document the rule.
     - The bind IP rules are unchanged, and the bind IP is never 0.0.0.0.
2. **Apache in UAT mode.** crm-app must not set `HTTPS on`. It still removes `X-Forwarded-Proto` before EspoCRM sees it, so no client can choose the scheme.
   - Use a second Git-controlled file, e.g. `deploy/beta/apache/crm-proxy-uat.conf`, chosen fail-closed from `CRM_BETA_MODE`.
   - Extend `check_proxy_conf` and the compose allowlist so that exactly the file for the mode is mounted. Production must still mount `crm-proxy.conf`, and no mode may mount a file that the policy hasn't checked.
   - The design is yours, but the selection must be validated by `check_access.py beta`, and `deploy_release.sh` must not depend on a manual edit of the rendered or deployed tree.
3. **Edge template.** The same template serves both modes. `@CRM_BETA_UPSTREAM_SOURCES@` renders networks in UAT mode. In both modes the edge denies every other source with 403.
4. **`deploy_release.sh`.**
   - Set `siteUrl` from `CRM_SITE_URL` in both modes; this already happens, so keep it.
   - Print the mode, without any address, in its output.
   - The env-file name stripping and every other guard are unchanged.
5. **`provision_users.py`.**
   - Accept the target `beta` as well as `dev`, with the pinned base URL (`check_access.base_url_problem`), as `provision_access.py` already does.
   - Add `--service-identity <sfId>` (repeatable). The identity is provisioned **inactive**, with an unusable password that is never recorded. Its names are kept (unlike `--legacy-shared`, which renames), and `--reset` is refused for it. This is for non-person Salesforce logins, such as integration or shared mailboxes, so that their records keep an owner.
   - Add `--common-password-file FILE`, allowed only for target `beta`.
     - FILE must be a root-owned regular file, mode 0600, not a symlink (open it with O_NOFOLLOW). It must hold one line: a password of at least 16 characters with at least three character classes.
     - Every **new active** user who is not legacy-shared and not a service identity gets this password, instead of a generated one.
     - Nothing is written to `--password-file` for those users. In this mode `--password-file` is optional; when given, it records only generated passwords.
     - The password is never printed or logged. `sendAccessInfo` stays false.
     - Re-runs never touch passwords (unchanged).
     - The admin user and the ER Import API user are never affected.
6. **`scripts/uat_records.py beta`** (read-only, admin credentials from the environment as the other scripts, pinned base URL).
   - Report counts only, per entity (Account, Contact, Opportunity, Task, Call, Meeting, Email), of records with an empty `sfId`. These are records created during UAT, which must be removed before production migration.
   - Optionally add `--list-ids` to write their EspoCRM ids to a new 0600 file.
   - It makes no writes.
7. **Docs:**
   - `docs/BETA.md`: a "UAT mode" section covering what changes, what does not, and the risks accepted by the PO (plain HTTP on the LAN; a common temporary password).
   - The steps to return to production mode: HTTPS, unique passwords, activation controls.
   - `docs/ACCESS.md`: the new flags.
   - `deploy/beta/env.example`: names only, including `CRM_BETA_MODE`.
